Cheat-sheet table content for "## Quick-reference: widgets and attachments":

  | Widget | APVTS attachment | Parameter type | Use for |
  |--------|-----------------|----------------|---------|
  | `Slider` | `SliderAttachment` | `AudioParameterFloat` | Airwindows float A-Z (0.0-1.0) |
  | `ToggleButton` | `ButtonAttachment` | `AudioParameterBool` | On/off switches, mode flags |
  | `ComboBox` | `ComboBoxAttachment` | `AudioParameterChoice` | Algorithm variants, integer choices |
  | `TextButton` | none | n/a | Trigger actions (reset, preset load) |
  | `Label` | none | n/a | Knob labels, dynamic value display |
  | `TabbedComponent` | none | n/a | Multi-processor layouts (chained plugins) |
  | Custom `Component` | none | n/a | VU meters, waveform display, visual feedback |
  | `GenericAudioProcessorEditor` | automatic | all APVTS params | No-UI fallback, testing, prototyping |

Section-by-section instructions (use research §3 code verbatim or near-verbatim):

  1. APVTS setup (research §3.1): constructor pattern with createParameterLayout(), mapping
     Airwindows float A/B/C to AudioParameterFloat with NormalisableRange<float>(0.0f, 1.0f).
     Include processBlock read: float A = *apvts.getRawParameterValue("compress").
     JUCE 7->8 note: APVTS API is identical — no breaking changes.

  2. AudioProcessorEditor structure (research §3.2): class declaration showing member order
     (Slider declared BEFORE SliderAttachment — destruction order rule). Constructor using
     initializer list: compressAttachment(apvts, "compress", compressSlider).
     Explicitly call out the destruction order rule in a comment.

  3. Slider — rotary and linear (research §3.3): RotaryVerticalDrag and LinearHorizontal.
     Note: setRange() not needed when using APVTS attachment.

  4. Label (research §3.4): static label + dynamic value display via knob.onValueChange lambda.

  5. TextButton (research §3.5): onClick lambda. Note: not for Airwindows 0-1 params;
     use for bypass / init / reset.

  6. ToggleButton + ButtonAttachment (research §3.6): AudioParameterBool in layout,
     ButtonAttachment wiring, setButtonText.

  7. ComboBox + ComboBoxAttachment (research §3.7): AudioParameterChoice in layout,
     addItem calls (IDs start at 1). JUCE 8 note: ComboBoxAttachment maps choice index 0
     to item ID 1 automatically; manually added items must start at ID 1.

  8. TabbedComponent (research §3.8): addTab with owner=true. setBounds(getLocalBounds())
     in resized(). Note use case: chained Airwindows processors (console + tape + eq).

  9. Custom paint() (research §3.9): GainMeter component with juce::Timer.
     startTimerHz(30). g.fillRect driven by 0.0-1.0 float from processor.

  10. GenericAudioProcessorEditor (research §3.10): return new juce::GenericAudioProcessorEditor(*this)
      from createEditor(). JUCE 8 note: respects ParameterGroup for collapsible sections.

Quick-reference checklist content for end of doc:
  - [ ] APVTS declared in processor header and constructed with createParameterLayout()
  - [ ] One AudioParameterFloat per Airwindows A-Z param, NormalisableRange(0.0f, 1.0f)
  - [ ] Slider (or other widget) declared BEFORE its attachment in the editor class
  - [ ] Attachment constructed in editor constructor initializer list: attachment(apvts, "id", widget)
  - [ ] addAndMakeVisible called for every widget in the constructor
  - [ ] resized() sets bounds for all widgets
  - [ ] Timer started for any custom paint components: startTimerHz(30)
  - [ ] GenericAudioProcessorEditor used for initial testing before building custom editor
